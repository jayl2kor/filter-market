# moodit · 신규 PM 30/60/90 Day Plan

> "신규 PM의 첫 90일은 *이해 → 신뢰 → 결과*". 본 plan은 그 3개 phase에 어떤 산출물을 *측정 가능한 기준*으로 만들지 정의한다.
> **Day 1 = 인수인계 시작일**. 본인의 Day 1을 상단에 기록하고 진행하세요.

```
Day 1: 2026-__-__       (현 PM 작성)
Day 30 게이트: 2026-__-__
Day 60 게이트: 2026-__-__
Day 90 게이트: 2026-__-__
```

## Phase A — Days 1~30: 이해 (Learn)

**테마**: 코드·문서·사람·고객을 이해. 결정은 최소화.

### 산출물 (Day 30 게이트)

| # | 산출물 | 측정 기준 | 보관 위치 |
|---|---|---|---|
| A1 | 본 인수인계 패키지 완독 + 주석 노트 | 11개 폴더 14개 문서 모두 ✓ | 개인 노트 |
| A2 | 빌드/테스트 직접 실행 결과 | `./scripts/test.sh` 1회 PASS, 결과 로그 첨부 | `docs/PHASE_ROADMAP_STATUS.md` §11 |
| A3 | 핵심 사람 1:1 (5명 이상) | iOS 리드, 백엔드 리드, 디자이너, QA, 창립자 | 1:1 노트 |
| A4 | 페르소나 인터뷰 (3명) | P1·P2·P3 각 1명 30분 인터뷰 노트 | `prd/PERSONAS.md` 부록 |
| A5 | 본인 첫 인상 메모 | 무엇이 강점·약점인지, 후임이 알면 좋을 것 | `stakeholder-brief/FIRST_IMPRESSIONS.md` 신규 |

### 의사결정 *최소화* 원칙
- 이미 선언된 결정(§5 NEW_PM_BRIEF)은 *3주차까지 그대로 유지*.
- 변경하고 싶은 결정은 메모만 남기고 4주차에 검토.

### Day 30 self-check 질문
- [ ] WAFA 측정이 어디에서 어떻게 되는가? 답할 수 있는가?
- [ ] `.fmpkg`가 무엇이고 어떻게 만들어지는가?
- [ ] 신고 1건이 들어왔을 때 24h 안에 어떻게 처리되는가?
- [ ] 결제 1건이 실패했을 때 사용자가 어떻게 환불받는가?
- [ ] Apple 심사가 *오늘* 들어와도 통과 가능한가? 아니라면 무엇이 막는가?

## Phase B — Days 31~60: 신뢰 (Earn)

**테마**: 작은 약속을 정확히 지키며 신뢰 적립. 큰 결정은 ADR로 남긴다.

### 산출물 (Day 60 게이트)

| # | 산출물 | 측정 기준 | 보관 위치 |
|---|---|---|---|
| B1 | Phase 1 닫기 작업 *주관* | `.fmpkg` 다운로드/캐시/적용 path 통과 (E2E 테스트 1건 추가) | PR + `docs/PHASE_ROADMAP_STATUS.md` |
| B2 | 실기기 FPS 측정 1회 (iPhone 12 mini, 13, 15 Pro) | 평균 FPS + thermal 결과 표 | `docs/M0_DEVICE_VALIDATION.md` 갱신 |
| B3 | TestFlight Internal 베타 5명 dogfood | 1주 사용 후 피드백 노트 + 크래시율 < 1% | `docs/QA_FINDINGS.md` 갱신 |
| B4 | Comments→Reviews 마이그레이션 마무리 | route/screen/notification 모두 reviews 키 | grep `Comment` → 0 결과 |
| B5 | KPI 대시보드 v0 구축 | Firebase Analytics + PostHog 연동, WAFA 표시 | URL 공유 |
| B6 | ADR 1건 작성 | 검색·추천 기술(Algolia vs Typesense vs 자체) | `docs/ADR/0004-search-engine.md` 신규 |
| B7 | 위험 1건 클로즈 또는 mitigated 전환 | R-T03 또는 R-O03 둘 중 1건 | `risks/RISK_REGISTER.md` 갱신 |

## Phase C — Days 61~90: 결과 (Deliver)

**테마**: Phase 게이트 1개 *실제로* 닫는다. App Store 게이트 평가.

### 산출물 (Day 90 게이트)

| # | 산출물 | 측정 기준 | 보관 위치 |
|---|---|---|---|
| C1 | **Phase 1 완료 선언** | TestFlight Internal 통과 + 회귀 그린 + 실기기 FPS 통과 | `docs/PHASE_ROADMAP_STATUS.md` §2 |
| C2 | TestFlight External 1차 (50명) | 1주 사용 후 D1 ≥ 30%, 크래시 < 1% | App Store Connect |
| C3 | App Store Production 진입 *결정서* | Go / No-Go ADR + 무엇이 막는지 표 | `docs/ADR/0005-app-store-go-decision.md` 신규 |
| C4 | Phase 3 social/review API persistence 80% 통과 | follow/review/notification 실 backend | PR 시리즈 |
| C5 | 첫 모더레이션 1건 처리 | 24h SLA 내 완료 (실기 데이터) | `risks/RISK_REGISTER.md` R-O03 mitigated |
| C6 | 다음 90일 PRD 업데이트 | Phase 4 게이트 진입 조건, Android ADR 일정 | `prd/PRD.md` |

### Day 90 self-check
- [ ] App Store Production 진입까지 남은 *블로커* 5건 이하 식별
- [ ] WAFA 실측 가능, 트렌드(주간 변화) 발표 가능
- [ ] Phase 1 완료 / Phase 3 closing 가시성
- [ ] 신규 PM 후임자에게 본 패키지를 *그대로* 인계할 수 있는 수준 (자기 변경분 반영)

## 위기 상황 대응 (90일 어디서든)

| 상황 | 첫 액션 |
|---|---|
| App Store 리젝트 | R-B02/R-B03 즉시 점검, 영문 답변 24h 내 |
| 크래시율 > 5% (1시간 sustained) | iOS 리드와 즉시 hotfix 회의, Crashlytics rollback 검토 |
| 모더레이션 큐 24h+ 항목 비율 > 10% | BPO 외주 즉시 검토, 임시 자동 비공개 임계값 ↓ |
| Firestore 비용 > 매출 30% | 백엔드 리드와 캐싱·페이지네이션 강화, R-T05 escalation |
| 외부 SaaS 장애 (Firebase/Cloudflare) | 상태 페이지 확인 → 사용자 공지 → fallback 활성 |
